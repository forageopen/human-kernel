# Changelog

Notable changes to Human Kernel. Loosely follows [Keep a Changelog](https://keepachangelog.com/); pre-1.0, so versions are milestones, not stability guarantees.

## [Unreleased] - 2026-08-02/03 (second through fifteenth passes, spanning v0.1.0-mvd)

### Added (fifteenth pass - Founder Override: start/countdown mechanic for L-Theanine only)

Direct feedback asked for a start button + live countdown against a per-supplement effectiveness duration ("start time, effectiveness (fill in yourself) with recommendation... then start button, and have countdown for each"). Named explicitly rather than silently built: this is functionally the Phase 2 status-effect/"Active" mechanic the rebuilt spec gated behind a two-week Phase-0 adherence read that hadn't happened yet. Flagged back before building; confirmed as a deliberate Founder Override, scoped narrowly - not a blanket reopening of Phase 2.

Scope narrowed further before building anything: the five supplements don't share one effect profile. L-Theanine has a real acute onset/offset (the direct feedback's own example: "L-thenine effect is 5 half hour"). Creatine, Magnesium, Omega-3, and Vitamin D3+K2 are daily-baseline/cumulative supplements with no genuine "wears off" point - forcing a countdown number onto those would invent false precision, the same trap the disclaimer problem already caught once this feature. Confirmed with a direct question before writing any code; answer was to scope the countdown to L-Theanine only and leave the other four untouched.

- **`supplements.ts` extended**: every `Supplement` now carries a short generic `info` blurb (shown on every card - "so have info for each card") and an `effectProfile` of `"acute"` or `"baseline"`. Only L-Theanine is `"acute"`, carrying a `recommendedDurationMinutes` (150 - the direct feedback's own figure). New pure functions: `loadEffectDurationMinutes`/`saveEffectDurationMinutes` (user-editable, defaults to the recommended figure), `loadStartedAt`/`saveStartedAt`/`clearStartedAt`, `remainingEffectMs`, `formatCountdown` (reads "Xh Ym remaining", or "Effect window ended" at zero).
- **`supplement-card.ts` gained a second card variant**: `renderAcuteSupplementCard`/`wireAcuteSupplementCard`/`resyncAcuteSupplementCard` - an editable duration input, a Start button, and a countdown display that cycles through not-started → running (Start hidden, Cancel shown, duration input disabled) → finished ("Effect window ended", Start available again). Pressing Start also silently logs the supplement taken for the day (`saveTakenOn`), so adherence data stays comparable across all five cards despite the UI differing. The four baseline cards (`renderSupplementCard`/`wireSupplementCard`, unchanged mechanism) also gained the new info line.
- **`reminder.ts`'s shared clock extended, not duplicated**: `startReminders` takes an optional third `countdownTargets` param: the same ~20s tick that already drives the baseline reminder checks now also refreshes the acute card's live countdown text and fires a one-time "effect window ended" toast/Notification the moment a running countdown crosses zero - same toast/Notification mechanism as the existing reminder, just a different trigger condition. No second timer.
- **`main.ts`**: branches per-card on `supplement.effectProfile`, not a hardcoded id, so reclassifying a supplement later is a data change in `supplements.ts`, not a code change here.

343 tests passing (up from 310), typecheck/build clean.

### Fixed (fourteenth pass - tab 2 theme, reminder-field wording)

Direct feedback after the thirteenth pass shipped, two items:

- **Tab 2 now follows the theme toggle** (`styles.css`'s `.hk-tab2-panel`): the previous pass hardcoded it to black regardless of the dark/light/feminine cycle, reasoned at the time as a deliberate third visual mode independent of `data-theme`. Direct feedback: "supplement tab got no feminine, light & dark mode." That reasoning is retired - the panel no longer overrides any themed CSS variable, so it now reads `var(--bg)` like everything else and switches with the rest of the app. Under the default dark theme this still looks near-black, which is what the original "black background" request meant in practice - it just isn't locked there anymore.
- **Reminder field relabeled** (`supplement-card.ts`): "Time" → "Remind me at". Direct feedback confirmed the taken/reminder mechanism itself is correct (ticked "Taken today" silences the reminder, unticked lets it fire once the time passes) but the wording didn't make the connection between setting a time and arming a reminder obvious. Label changed, mechanism untouched.

### Added (thirteenth pass - second product tab: Cognitive Supplement Dashboard, Phase 0 only)

Direct request for a second, Chrome-style tab alongside the existing dashboard: black background, its own taskbar with card toggles. Followed by a full rebuilt spec for what the tab actually contains, scoped hard to one open question - does a fixed-time reminder change whether a supplement gets taken consistently - and explicitly gated everything else (Daily OS window-model integration, a rules engine, status-effect UI, graphs) behind a two-week real-world adherence test. Phase 0 ships only: a fixed daily time per supplement (set by the user, not suggested), a reminder at that time, and a taken/not-taken checkbox. Nothing else.

- **`src/dashboard/tabs.ts`** (new) - owns only the switching mechanism (which panel is visible, remembering the choice), not either panel's content. `index.html` wraps all of tab 1's existing content in `#hk-tab1-panel` and the new tab in `#hk-tab2-panel`; toggling `.hk-tab-hidden` (`display:none`) on whichever one isn't active already hides everything inside it in one shot, background-animation layers included - a `display:none` ancestor hides fixed-position descendants too, so no separate per-layer pause/hide logic was needed. The tab bar itself mounts as the very first element in `<body>`, a sibling of both panels, so it's never hidden by its own switch.
- **The disclaimer problem, resolved before anything shipped**: a "recommended window" for a supplement is timing guidance, personalized, and "educational, not medical" doesn't survive that. Two honest options were on the table - state plainly that any timing is generic product-label guidance, or drop suggested windows entirely. Took the second: `src/dashboard/supplements.ts` ships with no default/recommended time anywhere in the data model or the UI - the user sets every time themselves, and the card says so directly (`"You choose the time. No suggested schedule."`) rather than hedging in a footnote.
- **`src/dashboard/supplements.ts`** (new) - the five supplements, unchanged from the original scope (Creatine Monohydrate, L-Theanine, Magnesium Bisglycinate, Omega-3, Vitamin D3+K2; Biotin and Iron stay out). Per-supplement set time and per-day taken/not-taken state, both in `localStorage`; all "today" logic runs on real Kuala Lumpur time (`Intl.DateTimeFormat` with an explicit timezone, the same convention `clock.ts` already established) rather than device-local time, so a reminder or a rollover never fires an hour off for a visitor in the wrong system timezone.
- **`src/dashboard/supplement-card.ts`** (new) - one card per supplement: a time input, a "taken today" checkbox, nothing else - no slider, no drag-and-drop, no status UI. Today's date key is recomputed fresh on every read/write rather than captured once, so a tab left open across a Kuala Lumpur midnight rollover writes to the correct new day instead of silently backdating to whenever the page loaded.
- **`src/dashboard/reminder.ts`** (new) - a single shared clock (~20s tick) drives both firing the reminder and keeping every card's checkbox honest across a midnight rollover, instead of five independent per-card timers drifting apart. Fires an in-page toast unconditionally (no permission needed) plus a browser Notification only on explicit opt-in - never requested automatically, since a permission prompt needs a real user gesture behind it anyway. Deliberately not a service worker/push subscription: "a reminder at each time" is satisfied honestly by a foreground check while the tab is open, not oversold as something that survives the tab or browser being closed. Runs regardless of which of the two tabs is currently showing.
- **`scene-panel.ts` gained an options param** (`ScenePanelOptions`, backward-compatible - every existing call site is unaffected): the shared background-motion-speed and firework-color-count sliders can now be excluded, and the panel/list headings overridden. Needed because tab 2's own taskbar instance reuses `renderScenePanel`/`wireScenePanel` unmodified in behavior, but has no ambient background or fireworks layer for those two sliders to mean anything to - shipping them anyway would have been controls that quietly did nothing a visitor could see, on a screen otherwise scoped to "nothing else."
- **Tab 2's black background** (`styles.css`'s `.hk-tab2-panel`): a deliberate third visual mode, independent of the existing dark/light/feminine theme cycle - both tabs share `<html>`'s one `data-theme` attribute, so tab 2's look is carried by re-declaring every themed CSS variable scoped to that one element instead (the same mechanism `[data-theme="light"]` already uses for the whole page, just scoped narrower). Every reused component inside - the widget chrome, the scene taskbar, the supplement card - inherits those values for free. Values are hardcoded to the dark tier (Forage Black, Ember Gold) rather than reading `var(--accent-text)`, since this surface is always dark and the brand guideline restricts Ember Gold to dark surfaces only - it must never silently swap to the light-theme Sage accent just because tab 1 happens to be in light mode.
- **`main.ts` wiring**: tab 2 gets its own canvas and its own five supplement widgets, built through the same `createWidget` every tab-1 card uses, plus its own scene-taskbar instance and reminder targets built straight from those widgets so the two can never fall out of sync.

- **`src/dashboard/quotes.ts`** (new) - a curated bank of quotes hand-picked from an uploaded source file, verbatim (excerpted with a marked "…" cut for anything too long to include whole, never paraphrased; a handful of raw entries were dropped outright rather than force-excerpted - a citation cut off mid-sentence in the source, several numbered lists that only make sense whole, one passage whose provenance as possibly-adapted-poetry couldn't be confirmed). Original ALL-CAPS emphasis and source-quirk spelling/grammar preserved as typed; a `poetic` flag marks the handful with real verse structure for italic rendering. `computeDisplayDurationMs` scales 7-11s by quote length, direct request.

- **Taskbar card/avatar reordering** (`scene-panel.ts`): a drag grip on every row, vanilla pointer events (same philosophy as `draggable.ts`'s card dragging, not the native HTML5 drag-and-drop API) - dragging live-reorders the DOM past whichever sibling's midpoint the pointer crosses, release persists the final order. Scoped to the taskbar's own list order only, not each card's actual canvas position - a separate, already-solved concern. Mascot/dog are just more entries in the same list, so "cards & avatars" are covered by one mechanism.
- **Editable Notes titles** (`draggable.ts`'s `createWidget` gets a new opt-in `editableTitle` option, enabled only for the 5 Notes widgets): click (or Enter/Space) turns a card's title into an editable field; Enter or clicking away commits and persists per-widget; Escape cancels; a blank commit falls back to the original default rather than saving empty.
- **Editable profile header** (`src/dashboard/profile-name.ts`, new): the same click-to-edit interaction, applied to `index.html`'s `#hk-profile-name` - "Adam Rosman" is now a starting default, not a hardcoded identity; anyone can write their own name or a project title. Reimplemented rather than routed through `createWidget`, since the header isn't a widget (no drag handle, no close button, not on the canvas).
- **Sample-profile banner retired** (`render.ts`'s `renderSourceBanner` returns `null` for the sample view): "You're looking at a real example profile - Adam's own" and "Use my own notes instead" no longer render. The underlying vault-connection code (`onConnectOwnVault`, the File System Access picker in `app.ts`) is untouched - only this banner's sample-view text was retired, not the feature.
- **Profile stats line retired** (`index.html`'s `.hk-profile-stats` div removed, `main.ts` no longer passes `statEls`): the "N notes captured/N traits tracked" line is gone. `app.ts`'s `wireBrowserUI` keeps `statEls` as an optional parameter rather than being edited, so this needed no other change.
- **Brand rename**: "Human Kernel" → "Human on Cloud" in the page `<title>` and top-ribbon brand text. Footer credit changed from `Built by [Adam Rosman](github.com/forageopen) with Claude (Anthropic) — see [Credits]` to `[Adam Rosman](github.com/adamrosmanx) for [Forage](github.com/forageopen) — see [Credits]`.
- **Individual background-layer toggles** (`main.ts`): fireflies (`particles.ts`), lasers (`starchase.ts`), sakura, and fireworks each get their own scene-taskbar entry, same `loadVisible`/`saveVisible` + `.hk-widget-hidden` mechanism as the mascot/dog avatars. ### Fixed (theme toggle button label)

Direct bug report after the tenth pass shipped: "wrong labelling - feminine supposedly the pink one, light mode supposedly the light color, dark mode also affected." Root cause - `wireThemeToggle` (`src/dashboard/theme.ts`) labeled the button with the NEXT theme in the cycle (what clicking it would switch to), not the one currently on screen. With only two modes this was a minor convention; with a third, visually distinct Feminine palette added, it meant every mode looked "wrong" at once - dark colors on screen while the button read "Light mode," light on screen while it read "Feminine mode," and so on around the cycle. Fixed to label the button with whatever theme is actually active; `index.html`'s static pre-hydration fallback text updated from "Light mode" to "Dark mode" to match the real default.

### Added (eighth pass - generic show/hide chrome, a real calendar, two new Layer-3 cards, a scene taskbar, a second background layer, and a mascot)

Ten-part direct instruction, in full: fix the close (×) button on every card; rebuild Activity as a real calendar instead of a scrolling strip; fix the notepad highlighter's contrast; allow up to 5 Notes cards; build an auto-hide left taskbar to show/hide any card and control background-animation speed; introduce Layer 3 of the Adaptive Daily OS as new cards; add a purple 8-bit mascot "cousin" of the Claude Code avatar; add a second background layer of two star groups chasing each other; and update the profile bio copy.

- **Generic widget chrome** (`src/dashboard/draggable.ts`'s new `createWidget()`): every card - all 11 of them - is now built through one function, so drag, native resize, a close (×) button, and a show/hide state all behave identically everywhere instead of each card reinventing its own chrome. Closing a card never removes it from the DOM or destroys its state (a running prayer countdown, unsaved note text) - it's `display:none` via `.hk-widget-hidden`, reversible from the card itself or from the new scene taskbar. Click-to-open-evidence is re-wired fresh on every `renderMonth()` call, including after Prev/Next - an earlier draft wired it once, externally, which would have silently broken day-clicks on every month after the first.

- **Up to 5 independent Notes cards** (`notepad.ts`'s functions all now take an instance `id`; `main.ts` creates all 5 upfront): instance `"1"` migrates forward from the old single-notepad storage keys exactly once, so nobody's already-typed note vanishes just because multi-instance support landed later. - **Scene taskbar** (`src/dashboard/scene-panel.ts`, new): an auto-hide panel pinned to the left edge (pure CSS `:hover`/`:focus-within`, plus a click-toggle for touch/keyboard) listing every card on the canvas with a live show/hide switch, plus a slider controlling the shared background-motion speed. Hover to squint; click-and-hold to drag anywhere in the viewport (unconstrained by the card canvas); release to have it fall like a leaf - a swaying multi-keyframe descent, skipped under `prefers-reduced-motion` - to a resting spot near the bottom of the viewport, which persists for next visit. Purple (`#8b7ec8`/`#5f4f96`) is a deliberate, explicitly-flagged one-off outside the locked Forage palette, restricted to this one decorative character.
