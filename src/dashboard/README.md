# dashboard

Wired and unit-tested as of this commit — read the honest version of that claim below before assuming more than it says.

## What's real

The whole-page overview/domain-grid/6-chart-card design described in earlier revisions of this file is gone. As of 2026-08-02 the dashboard is a free-form **widget canvas**: every card - including all 5 Notes slots - is created dynamically through `draggable.ts`'s `createWidget()`, which gives each one identical chrome (drag, native `resize:both`, a close (×) button, and a show/hide state the scene taskbar can also flip) with no per-card boilerplate. `main.ts` builds the canvas once; nothing in this directory destroys or recreates it afterward (see `render.ts`'s top-of-file note for exactly why that split matters).

As of 2026-08-03 (second pass) there are **two tabs**, Chrome-style: this dashboard (unchanged, described throughout this file) and a second, independent Cognitive Supplement Dashboard - `tabs.ts` owns only the switch between them. The second tab is Phase 0 only by deliberate scope decision (see `supplements.ts`'s header) - a fixed user-set time per supplement, a reminder, a taken/not-taken checkbox, nothing else. Everything past that (Daily OS window-model integration, a rules engine, status-effect UI, graphs) is gated behind a two-week real-world adherence test that hasn't run yet.

- `render.ts` — pure DOM rendering, but only for the **vault-reactive** slice: source banner, rescan toolbar, warnings panel, empty-state line, and the calendar's content (via `heatmapBody`, a stable element inside the persistent canvas). Also owns the evidence detail drawer (`renderDrawer`/`closeDrawer`), which now opens by calendar-day click rather than by Parameter card. Covered by `render.test.ts` (jsdom).
- `charts.ts` — `renderCalendarHeatmap()`: a traditional month calendar (Prev/Next, one month on screen at a time), not the earlier GitHub-contribution-style scrolling strip - that was replaced after direct feedback that it was "too long to scroll." Cell intensity coloring (`.hk-heatmap-cell level-N` + the Less→More legend) is reused, unchanged, from the original heatmap design. Covered by `charts.test.ts`, including a regression test for re-wiring day-click handlers after Prev/Next navigation.
- `draggable.ts` — `makeDraggable()` (drag-to-move + persisted rect) plus `createWidget()`, the one function every card on the canvas is built through. Also owns each widget's visibility state (`loadVisible`/`saveVisible`, `localStorage`), which both the card's own close button and the scene taskbar's toggles read and write, plus its title state (`loadTitle`/`saveTitle`) for the opt-in `editableTitle` option - click (or Enter/Space) to rename, Enter/blur to commit, Escape to cancel, a blank commit falls back to the original default. Only the 5 Notes widgets enable `editableTitle`; every other card's title is fixed. Covered by `draggable.test.ts`.
- `profile-name.ts` — the same click-to-edit interaction as `createWidget`'s `editableTitle`, applied to the page header (`#hk-profile-name`) instead of a canvas card. Reimplemented rather than routed through `createWidget`, since the header has no drag handle, no close button, and isn't on the canvas - forcing it through that machinery would mean carrying widget-only concerns into page chrome that has neither. "Adam Rosman" is a starting default, not a hardcoded identity. Covered by `profile-name.test.ts`.
- `scene-panel.ts` — the auto-hide left-edge taskbar: a live show/hide switch for every card on the canvas, both roaming avatars (mascot, dog), and all 4 background layers (fireflies, lasers, sakura, fireworks); a slider controlling the shared background-motion speed (`--hk-speed`, read by `particles.ts`, `starchase.ts`, and `sakura.ts`); a second slider controlling how many colors `fireworks.ts` draws from for its next burst; drag-to-reorder on the card/avatar list itself (vanilla pointer events, persisted order applied on next render - the taskbar's own list order only, not any card's actual canvas position); and a footer slot holding the quote widget. Open/close itself is pure CSS (`:hover`/`:focus-within`/`.open`) - fully hidden at rest, no tab visible until the panel is hovered, focused, or opened; this file only keeps the toggles truthful and persists the slider/order choices. `renderScenePanel` takes an optional `ScenePanelOptions` (2026-08-03, second pass) so a second instance can drop the speed/firework sliders and override the panel/list headings - added for tab 2's taskbar below, backward-compatible for every existing call site (both default to the original behavior). Covered by `scene-panel.test.ts`.

### Tab 2: Cognitive Supplement Dashboard (2026-08-03, second pass - Phase 0 only)

A second, independent tab - own canvas, own scene-taskbar instance (via the `ScenePanelOptions` above), own black visual theme (`styles.css`'s `.hk-tab2-panel`, scoped CSS-variable overrides, not a third `data-theme` value - see its own comment for why). Scope is deliberately minimal: a fixed user-set time per supplement, a reminder, a taken/not-taken checkbox, nothing else - no time slider, no drag-and-drop scheduling, no rules engine, no status effects, no graph. Everything past that is gated behind a two-week real-world adherence test that hasn't run yet, not built speculatively ahead of it.

- `tabs.ts` — owns only the switching mechanism: which of `#hk-tab1-panel`/`#hk-tab2-panel` is visible (`.hk-tab-hidden`), and remembering the choice. Not either panel's content - main.ts wires that. `index.html` wraps ALL of tab 1's existing content inside `#hk-tab1-panel`, so hiding that one element hides everything inside it in one shot, background-animation layers included. Covered by `tabs.test.ts`.
- `supplements.ts` — data + pure logic only (no DOM): the five supplements (Creatine Monohydrate, L-Theanine, Magnesium Bisglycinate, Omega-3, Vitamin D3+K2 - Biotin and Iron stay out, unchanged from the original scope); per-supplement set time and per-day taken state in `localStorage`; `isReminderDue`. Ships with no default/suggested time anywhere - see its header comment for the disclaimer reasoning (dropping suggested windows entirely rather than hedging them). All "today" logic runs on real Kuala Lumpur time (`currentKlTime`/`currentKlDateKey`, the same `Intl.DateTimeFormat`-with-explicit-timezone convention `clock.ts` established), not device-local time. Covered by `supplements.test.ts`.
- `supplement-card.ts` — one card's worth of UI: a time input, a "taken today" checkbox, and a line explaining why the time field starts blank. `resyncSupplementCardCheckbox` is exported separately from the render/wire pair because `reminder.ts`'s shared clock (not each card's own timer) is what keeps it honest across a midnight rollover. Covered by `supplement-card.test.ts`.
- `reminder.ts` — one shared ~20s clock for every supplement card: fires an in-page toast (no permission needed) plus an optional browser Notification (explicit opt-in only, never auto-requested), at most once per Kuala-Lumpur calendar day per supplement. Deliberately not a service worker/push subscription - a foreground check while the tab is open is what "a reminder at each time" honestly means at this scope, not oversold as surviving a closed tab or browser. Runs regardless of which of the two tabs is currently showing. Covered by `reminder.test.ts`.
- `quotes.ts` / `quote-widget.ts` — a curated, categorized (`islamic`/`philosophy`/`relationship`/`dream`) quote bank and the widget built on it. `quotes.ts` is pure data + pure helpers (no DOM, no `localStorage`) - verbatim entries, a hard length ceiling (`MAX_QUOTE_LENGTH`), and `computeDisplayDurationMs` scaling 7-11s by length. `quote-widget.ts` shuffles each category into a play queue that reshuffles on exhaustion without repeating the seam quote, auto-advances on its own per-quote timer, and also advances on every taskbar hover-open. The category-cycle button always shows the CURRENT category, never the next one - the same rule `theme.ts` had to learn the hard way. Covered by `quotes.test.ts`/`quote-widget.test.ts`.
- `particles.ts` / `starchase.ts` / `sakura.ts` — three ambient background layers sharing one speed control, all pure-CSS-keyframe-driven (no canvas, no per-frame JS). `particles.ts` is the original slow drifting-dot field; `starchase.ts` is two color groups on opposite diagonals chasing each other; `sakura.ts` is falling cherry-blossom petals with their own sway/rotation. All three use the same bare-number-CSS-custom-property pattern, divided by `--hk-speed` in `styles.css`, so none of them has any JS-level notion of "speed." Covered by `particles.test.ts`/`starchase.test.ts`/`sakura.test.ts`.
- `fireworks.ts` — a fourth background layer, periodic radiating bursts. Unlike the three above, this one is genuinely timer-driven (a burst has to appear and disappear, not loop forever) and does NOT share `--hk-speed` - its color-count slider (1-24 hues) is a real JS-level choice, wired through its own callback from `scene-panel.ts`. Covered by `fireworks.test.ts`.
- `mascot.ts` / `dog-avatar.ts` — two free-roaming avatars, independent of the canvas. `mascot.ts` is a purple 8-bit character: hover to squint, click-and-hold to drag anywhere in the viewport, release to have it fall like a leaf to a resting spot near the bottom, which persists. `dog-avatar.ts` is fully autonomous (no pointer events) - it walks the full viewport width and back, flipping to face its direction of travel, with a continuous hop from a second, independently-animated nested element. Both use the same pixel-grid SVG technique as `avatar.ts`; both get an on/off switch in the scene taskbar via `draggable.ts`'s `loadVisible`/`saveVisible` applied directly to their elements (wired in `main.ts`, not in either file). Covered by `mascot.test.ts`/`dog-avatar.test.ts`.
- `avatar.ts` — the profile header's generated 8-bit portrait; click (or Enter/Space) regenerates and remembers the new one.
- `theme.ts` — 3-way theme cycle (`data-theme` on `<html>`: dark -> light -> feminine -> dark), persisted, defaults to dark per the Forage brand guideline. Feminine (light pink/maroon) is a direct-request addition explicitly flagged as a personal exception outside the two locked Forage tiers (Dark x Ember Gold, Light x Sage) - never presented as official brand identity.
- `clock.ts` — live footer clock, Asia/Kuala_Lumpur, text only. Pure formatter plus a thin `setInterval` wrapper. Covered by `clock.test.ts` using fake timers.
- `prayer-times.ts` — Upcoming Prayer card, real JAKIM data (`api.waktusolat.app`), fetched at most once a day.
- `time-window.ts` — Time Window / Best Time For cards: real content from Adam's Adaptive Daily OS (Layer 2, the Six-Window ROI Map), re-rendered every 60s so the "current window" highlight stays live.
- `cognitive-currents.ts` — two cards for Layer 3 of the same document (the Cognitive Cue System): a Mind-work/Hand-work toggle, and the document's own 3-question retrospective test for logging unplanned activity. Covered by `cognitive-currents.test.ts`.
- `notepad.ts` — up to 5 independent notepad instances (contenteditable + a Bold/Italic/Underline/Strikethrough row, same iconography as the Windows Sticky Notes reference screenshot, + a 24-color highlighter row that scrolls horizontally instead of wrapping, plus a "no color" de-select swatch). Every function takes an `id`; instance `"1"` migrates forward from the old pre-multi-instance storage keys exactly once. Highlighting always sets dark text on the highlight color for contrast, regardless of theme; de-selecting hands both back to transparent/inherit. `HIGHLIGHT_COLORS` is systematically generated (24 evenly-spaced pastel hues), same reasoning as `fireworks.ts`'s `paletteForCount`. Covered by `notepad.test.ts`.
- `app.ts` — `runVaultScan()` wires vault-reader → evidence-parser → compiler → store; takes its deps as arguments so it's testable with a fake vault, no real browser needed (`app.test.ts`). `wireBrowserUI()` is the thin, deliberately-small, NOT-unit-tested glue that touches `window`/`document` for real and does the ADR-0003 feature-detect before ever calling `vault-reader.pickVault()`.
- `../main.ts` + `../../index.html` + `../../styles.css` — the actual page. `index.html`'s canvas starts empty; `main.ts` is the only place that calls `createWidget` for each card, so it's the one file that knows the full current card list.

**Removed, so don't go looking for them:** the 6 Chart.js-backed overview cards, the domain-grouped Parameter card grid, any "SWOT" naming, and the Immersive/Inspect mode toggle - all scrapped on 2026-08-02 per direct instruction, well before the widget-canvas rebuild described above. If you want a literal SWOT/DISC/causal-map/timeline card, that's a product decision (probably a new optional `Parameter` field), not a rendering task - nothing in the schema currently defines that mapping. Also removed (2026-08-03): the sample-view source banner's "You're looking at a real example profile" text and its "Use my own notes instead" link (`render.ts`'s `renderSourceBanner` returns `null` for the sample view now - the underlying vault-connection code is untouched, only this banner's sample-view text was retired), and the profile header's "N notes captured/N traits tracked" stats line (`index.html`'s `.hk-profile-stats`, `app.ts`'s `statEls` param on `wireBrowserUI` stays optional and is simply never passed).

## What's NOT real yet

- **No manual click-through of the File System Access vault-picker flow has been done** — a real folder, picked by a real person, in Chrome/Edge/Brave. That specific path is still "wired and passes unit tests with fakes," not confirmed end to end.
- The bundled reference profile's fetch-and-render path (the one every visitor actually sees first) **has** been clicked through live on the deployed site.
- Live file watching — vault-reader has no watch/subscribe primitive (see its own file); re-scan today is manual (the "Refresh from my notes" button), not automatic on save.
- Layer 1 of the Adaptive Daily OS (the hour-by-hour Ideal Visualized Routine) - the source document points to a separate file (`24H-Adaptive-Daily-OS-v2.md`) that hasn't been supplied yet, so no card claims to represent it.

**Boundary rule (non-negotiable, Tension C), still holds:** `render.ts` only renders what it's given; `app.ts` is the only thing in this directory allowed to call `vault-reader`, `evidence-parser`, `compiler`, or `store`.
